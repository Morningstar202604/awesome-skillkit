## 二、绿数字可信度判定（QA 结论，原样采信）

- **可信**：566 单测（实测 collect=567）；LLM 场景产物内容（office/document_pipeline 等真实可用）
- **半可信**：154/154 场景（脚本侧 rc0+非空即 pass，matched:false/confidence:0.0 也判过）

## 三、P0 问题（毫不留情，原话转达）

1. **E2E 绿数含虚构交付物**（QA）：对外宣传口径若被第三方复现即翻车。修法：语义验收（声称的文件必须真实存在+可执行+测试过）、matched:false 判 fail、pending_realgen 剔除 headline。
2. **pii_scan `--strategy replace` 空实现**（代码质量）：合法选项静默按 mask 处理——用户以为数据已替换删除，实际只是打码。安全工具语义欺骗，P0。
3. **model_solver MIP 静默错解 + elapsed_ms 伪造 0**（代码质量）：整数约束被静默丢弃返回 success；全库唯一伪指标。应改返回 unsupported。
4. **依赖零锁版本**（安全）：requirements.txt 13 项全裸包名、无 lockfile、CI 裸装——典型供应链软肋。
5. **发布链绕过质量门**（安全）：pages.yml 无 `needs:gate`，main 直推即上站+发包。
6. **分发单点**（架构+技术债）：仅 Claude Code 一种安装范式、单 GitCode 宿主，与 superpowers 13 种安装路径差一个量级；CI 是否真在 GitCode 上跑存疑。

## 四、P1 问题

- 77% 弱测试：核心求解/扫描/转换逻辑从未被强断言验证；gen_smoke 模板 `returncode in (0,1,2)` 连 --help 语义错都放行。
- 诚实性标注（method/data_source）覆盖率 <10%，与 README 宣传口径不符；「静默回退零容忍」有 3 处反例（pub_plotter 缺 key 静默演示数据、model_solver、pii_scan）。
- 链上下文接力需真实化：前环结构化产物传入后环参数，并断言后环输出包含前环实体。
- 上游 33 技能补的脚本（800-1660 行、无类型标注、215 行函数）质量低于自建域——「上游目录成质量洼地」。
- 跨平台：Windows 单机绿=环境耦合；无 cron 回归、无 Linux/Windows 双矩阵；TLS CERT_NONE、models.json 硬编码。
- bus factor=1：116 自研技能零贡献者、零 star，维护面线性膨胀。
- manifest 无每技能内容哈希；dist 无签名无 SHA256SUMS 无 SBOM；安全技能目录 __pycache__ 可能打进 dist。

## 五、P2 / 细节失控

- README 徽章与 manifest 版本口径漂移（架构组实测仍见 0.19.0 残留——发版同步流程需 CI 校验兜底）。
- prompt-injection-guard 仅 7 组正则，零宽字符/homoglyph 可绕过，应自我声明为 tripwire 而非 guard。
- 复杂度热点：api_scorecard 1660L、pir_generator 1637L、runbook_generator 215 行函数；依赖探测两套实现应抽共享模块。
- site/index.html 仅 87 行壳页，验证徽章/触发词能力弱。

## 六、与对标项目对比（架构组结论）

| 维度 | 本项目 | superpowers(273k★) | VoltAgent(30k★) | BehiSecc(10k★) |
|---|---|---|---|---|
| 定位 | 场景包+验证层 | 开发方法论 | 官方技能目录 | 技能聚合 |

**共识判断**：单点差异化（验证层+中文平台链）真实存在且正中市场空白（「无验证无测试无审查」是技能生态公认痛点）；但分发、曝光、社区差一个量级——「护城河建对了，修在无人区」。

## 七、团队给的三个月优先级（五人建议收敛）

1. **把测试变成产品**：站点每技能挂四级验证徽章（pytest/冒烟/场景门/链E2E）+ 154/154 报告可引用化，向 VoltAgent 与 5 个社区列表提交收录——把已建成的信任壁垒推到市场前。
2. **分发解锁**：Codex/Cursor/Gemini CLI 安装路径 + 多平台安装徽章；GitCode CI 实跑验证。
3. **修 P0 + 还债配额 20%**：pii_scan/model_solver 语义修复、E2E 语义验收改造、依赖 lockfile + pages 加 gate、SOTA 模板推广 2 个高流量域。
