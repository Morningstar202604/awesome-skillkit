# awesome-skillkit 技能「SOTA 加强」规范与评审清单

> 配套 `SKILL-STANDARD-v2.md`（结构/合规层）。本文件定义**内容深度层**——一个技能「对标当前最佳实践」的加强标准与可复核的评审清单。
> 起源：paper 域 3 技能（experiment-runner / lit-review / pub-plotter）标杆重写（2026-09-21）。可作为横向推广到其他域的统一尺子。

## 0. 核心命题

**「能跑」≠「写得好」。** 121/121 冒烟门禁只证明脚本 import 不崩、CLI 不崩；它不证明技能用了当前最佳工具链与方法论。本规范补「实质深度」这一维：

| 层 | 工具 | 证明什么 |
|----|------|----------|
| 结构合规 | `SKILL-STANDARD-v2.md` + validator | 技能能被机器发现/路由/执行 |
| 可运行 | `run_skill_smoke.py`（121/121） | 脚本真能跑 |
| **内容 SOTA（本文件）** | 人工对标 + 强测试 | 用了当前最佳方法、可复核、不造假 |

## 1. 判「薄」的四轴（审计脚本信号）

加强前先按这四轴定位缺口（`SKILL.md` 结构普遍达标，短板多在脚本方法学）：

1. **真实示例**：有无一个可操作的「输入 → 输出」样例（带真实数据片段，非占位符）。
2. **SOTA 工具链**：是否用了当前最佳库/命令/服务（而非朴素 regex/手搓/模拟冒充真实）。
3. **诚实性**：模拟数据是否显式标注、方法是否如实标 method、回退是否写进 warning。
4. **可复核**：结论是否可被第三方可复现（固定 seed、引用 DOI/抓取日期、p 值/CI 而非布尔「显著」）。

## 2. 标杆样板（paper 域 3 技能，可作为「SOTA 加强前/后」对照）

| 技能 | 加强前弱点 | 加强后（SOTA 做法） | 引入工具 |
|------|------------|---------------------|----------|
| experiment-runner | 「显著」= 均值超阈值（假 t-test） | 真 Welch t-test（p/Cohen's d/95%CI）+ 多后端 seed + env 指纹 + mlflow 钩子 | scipy（缺失时纯 stdlib 回退） |
| lit-review | 顺序连接引用图 + 硬编码趋势 | Semantic Scholar 真实引用/被引 + 共同引用图 + LLM/关键词共现合成 + 诚实来源标注 | S2 Graph API / arXiv / model_route |
| pub-plotter | 手拍 figsize、无字体嵌入、色板非色盲安全 | 真实期刊物理宽度 + `pdf.fonttype=42` + 色盲安全色板 + 可选官方 scienceplots | matplotlib / scienceplots |

每技能配套：SKILL.md 升到 v2（新工具/参数/约束）、脚本重写、**手搓强测试**（真输入+真断言）替换弱冒烟。

## 3. 加强动作清单（逐技能执行）

1. **读全现状**：SKILL.md + 全部 scripts + 现有测试。
2. **对标 SOTA**（联网核 2026 最佳实践）：该任务域当前主流工具/库/API/方法论。
3. **改脚本**：把「朴素/模拟/手搓」换成 SOTA 工具；保留离线回退（可移植性）；不造假（方法如实标注）。
4. **改 SKILL.md**：
   - description 补新工具/能力触发词（中英双语，≥5 短语）。
   - 「出版级/关键决策点」单独成节讲 **why**（如：为什么 `pdf.fonttype=42`、为什么按版面出图、为什么用 p 值而非阈值）。
   - 失败处置表补新工具的错误特征（429/403、字体未嵌入、非色盲安全色…）。
   - 「参考」节列 SOTA 工具链清单（包名/端点/方法），供后续维护更新。
5. **写强测试**（替换弱冒烟）：真输入 + 对 SOTA 行为的断言（如 `p_value` 存在、`font_embedded`、`co-cited` 边）。
6. **重跑门禁**：`run_skill_smoke.py` 确认不退化；强测试全绿。
7. **记 before/after**：写入域基准文档（示例率/约束率/引入工具/脚本行数变化）。

## 4. 评审清单（合并前逐条打勾）

- [ ] 至少 1 个真实「输入→输出」示例（含真实数据片段）
- [ ] 用到当前最佳工具/库（非朴素 regex/手搓）；有离线回退且不掩盖（method/source 如实标注）
- [ ] 关键数值/端点/版宽有来源（无「巫术常量」；时间敏感项标 `VERIFY BEFORE USE`）
- [ ] 结论可复核（固定 seed / DOI / 抓取日期 / p+CI 而非布尔）
- [ ] 失败处置表覆盖新工具的真实错误（限流/缺包/字体/色板）
- [ ] SKILL.md 讲清关键决策的 **why**
- [ ] 手搓强测试覆盖 SOTA 行为，且全绿；冒烟门禁不退化
- [ ] version 升档 + verified-date 更新；compatibility 如实列新依赖

## 5. 反模式（加强时绝不做）

- 把「模拟」结果当「真实」交付（假 t-test、顺序边冒充共同引用、静默演示数据）——一律显式标注 + 回退。
- 堆 MUST 不解释 why——模型在边缘情况会判错。
- 为「加强」引入作者机器专属绝对路径 / 不可达引用（G2 门禁会拦）。
- 只改文档不改脚本（内容对不上实现）。
- 加强后不跑门禁（可能把 121/121 打挂）。

## 6. 推广路线（paper 域 → 全库）

paper 域 3 标杆完成后，按同模板推广到其他域（优先级：有脚本 + 当前方法明显过时的技能先行）：
1. 逐域审计四轴 → 出 gap 报告（只读）。
2. 每域挑 2-3 个最高杠杆技能做标杆重写。
3. 强测试 + 门禁回归 + before/after 基准。
4. 横向沉淀：把各域 SOTA 工具链并入本文件「SOTA 工具链」附录，形成全库统一尺子。

> 本文件的落地样例：`tests/_full_test_artifacts/paper_sota_benchmark.md`（paper 域 before/after 量化基准）。
