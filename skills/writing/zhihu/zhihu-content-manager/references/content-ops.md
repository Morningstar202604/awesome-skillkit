# 知乎内容运营策略（可自定义）

> 本文件是**可替换的个人风格基线**，不是平台硬规则。
> 平台硬性格式检查请运行 `scripts/zhihu_html_lint.py`，与本文件无关。
> 复制本文件，按你的账号定位修改后使用。

## 排版要求

- **长文深度**：每篇文章 7000-10000 字，内容丰富深入
- **多级标题**：h2 大章节带中文编号（"一、""二、"），h3 小节带数字编号（"1.1""1.2"）
- **章节分割线**：大章节之间用 `<hr/>` 分隔
- **段落间距**：使用 `<p data-pid="X"><br data-text="true"/></p>` 空行段落方案（技术原理见 SKILL.md「经验教训」）
- **列表结构**：`<ul><li>` 列出结构化知识点、步骤、对比项
- **引用块**：`<blockquote>` 包裹名言、重要结论、历史背景
- **粗体强调**：关键术语用 `<b>` 加粗

## 视觉要求

- **封面图**：主题场景风格，避免纯渐变 PPT 风
- **正文插图**：每篇 3-5 张，均匀穿插在章节之间，内容与章节主题匹配
- **图片格式**：`<figure data-size="normal"><img src="URL" data-caption="说明"/></figure>`

## 内容风格

- **故事性开头**：以历史故事、场景描写或引人思考的问题开头
- **生动比喻**：用日常类比解释技术概念
- **历史背景**：技术演进要有时间线、人物、关键事件
- **实战导向**：代码示例、应用场景、常见误区
- **层次递进**：基础概念 → 核心原理 → 实战应用 → 进阶技巧
- **结尾升华**：总结核心价值，给出行动建议或学习路径

## 草稿箱盘点流程

1. 访问 https://www.zhihu.com/creator/manage/creation/all
2. 点击「草稿箱」标签，滚动加载所有草稿
3. 对每个草稿判断：
   - 纯图片无文字 → 删除
   - 内容 < 100 字 → 删除
   - 已有已发布版本 → 删除
   - 有实质内容但重复 → 只留最新，其余删除
   - 有实质内容且未发布 → 评估润色发布

## 内容润色流程

对于有价值但质量不达标的草稿：

1. 获取完整 HTML 内容
2. 检查结构：标题层次、段落间距、代码完整性
3. 扩充内容：补充历史背景、增加代码示例、添加应用场景
4. 统一风格：按本文件的排版与风格规范处理
5. 运行 `scripts/zhihu_html_lint.py` 确认格式检查通过
6. 生成封面图和正文插图
7. 发布到目标专栏
