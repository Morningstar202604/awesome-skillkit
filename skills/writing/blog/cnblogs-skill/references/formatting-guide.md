## 1. 核心风格：短段落多空行

这是用户最强调的排版要求。

**一句或几句话就空行，不要多段话挤在一起。**

### 正确示例

```markdown
2026年8月13日深夜，两件事同时发生。

DeepSeek开源了Harness框架——MIT协议，"一切皆插件"。

OpenAI被曝将于8月强行发布GPT-6——代号Astra，10万亿参数。

这两件事看似无关，其实指向同一个结论。
```

### 错误示例

```markdown
2026年8月13日深夜，两件事同时发生。DeepSeek开源了Harness框架——MIT协议，
"一切皆插件"。OpenAI被曝将于8月强行发布GPT-6——代号Astra，10万亿参数。
这两件事看似无关，其实指向同一个结论。
```

### 规则

- 每个完整意思结束后空一行
- 不要把多个观点挤在一个段落里
- 一句话也可以独立成段（尤其是关键结论、转折、数据）
- 表格前后各空一行
- 图片前后各空一行
- 分割线前后各空一行

## 2. 标题层级规范

### 规则

- **禁止使用 h1**（`# 标题`）：h1 与博客园页面标题重复
- **从 h2 开始**（`## 标题`），子节用 h3（`### 标题`）
- **标题层级不跳跃**：不能从 h2 直接跳到 h4
- **每个章节标题带 emoji**：增加辨识度和视觉节奏

### 正确示例

```markdown
## 📊 一、数据不会说谎：2026年薪资天平正在倾斜

### 1.1 本科起薪：硬件全面反超

### 1.2 中高级薪资：软件天花板更高
```

## 3. 段落与分隔

### 规则

- **段落之间用空行留白**，不用 `<br>` 标签
- **章节之间用 `---` 分割线**分隔
- `<br>` 在 Markdown 模式下不渲染，会显示为原始文本

### 正确示例

```markdown
这是第一段。

这是第二段。

---

## 📊 下一章节

正文内容。
```

---

## 4. 表格规范

### 规则

- 对比内容用 Markdown 表格
- 数字列居中对齐（`:---:`），文字列左对齐（`:---`）
- 表格前后各空一行

### 正确示例

```markdown
| 排名 | 专业 | 月薪（元） |
|:---:|------|:---:|
| 1 | 微电子 | 7814 |
```

---

## 5. 引用块规范

### 规则

- 每篇引用块（`>` 开头的段落）**不超过 5 组**
- 连续的 `>` 行算 1 组
- 用于强调关键结论或金句
- 不用引用块做大段引用

### 正确示例

```markdown
> 你每天写的每一行代码，都在喂养一个最终会取代你的模型。
```

---

## 6. 代码块规范

### 规则

- 代码块用三个反引号 ` ``` `，不能用两个 ` `` `
- 指定语言类型（```python, ```bash 等）
- 代码块前后各空一行

## 7. 配图排版

### 规则

- 每篇 2 张配图
- Markdown 语法：`![描述](URL)`
- 图片前后各空一行
- 第一张放在开头引言后（概念图）
- 第二张放在正文中间关键数据处（对比/趋势图）

### 图片插入方法

```python
body = body.replace(
    "目标文本段落。\n\n---",
    "目标文本段落。\n\n![图片描述](图片URL)\n\n---"
)
```

重要：replace 的目标文本必须**完全匹配**。如果匹配失败，先用 `find` 定位调试。

## 8. 签名区规范

### 规则

- 签名通过博客园系统 API 管理，不在文章正文中写
- 签名内容使用 HTML 标签，不用 Markdown
- 系统变量 `{author}` 和 `{post_url}` 自动替换

### 正确签名内容（HTML）

```html
<hr>
<p><strong>作者：{author}</strong></p>
<p>原文链接：<a href="{post_url}">{post_url}</a></p>
<p>本文为博主原创文章，转载请注明出处。</p>
```

### 签名管理方式

通过 API 管理（详见 `references/publish-api.md` 第9节）。

## 9. 文章结构模板

```markdown
## 🔥 抓人的开头标题

用一个故事、场景或冲突事件开头。

制造紧迫感。

**关键数据。**

- 观点A
- 观点B

本文要解决的核心问题。

![概念图](图片URL)

---

## 📊 一、第一个章节标题

### 1.1 子节标题

内容。

| 列1 | 列2 |
|------|------|
| 数据 | 数据 |

### 1.2 子节标题

内容。

> 关键结论引用。

---

## 📈 二、第二个章节标题

内容。

![对比图](图片URL)

---

## 📌 本文要点回顾

1. 要点一
2. 要点二
3. 要点三
```

### 结构要素检查

- [ ] 开头有引言和冲突感
- [ ] 每个章节标题带 emoji
- [ ] 章节间有 `---` 分割线
- [ ] 至少 2 个对比表格
- [ ] 引用块不超过 5 组
- [ ] 2 张配图（开头+中间）
- [ ] 文末"📌 本文要点回顾"
- [ ] 无 h1 标题
- [ ] 无 `<br>` 标签
- [ ] **短段落多空行**（最核心的风格要求）
