# Storyboard Designer

Break a video concept into an executable per-scene storyboard pack: beat sheet + paired per-scene "image-board prompt + video prompt" output + continuity constraint table. **The storyboard is the contract between design and generation — the tighter the contract, the less generation drifts.**

But a "contract" that is only format-compliant is useless: **a sequence of perfectly formatted shots that violate film grammar will cut together like schizophrenia**. This skill therefore builds in two layers: a format layer (scene_lint.py guards the door) + a grammar layer (a real storyboard artist's shot rules, checked manually).

## Pre-flight Checks

- Can the concept be told within the total duration? Scene count ~= total duration / per-scene duration (default 5s/scene).
- **Two numbers for per-scene duration**: scene_lint.py's hard boundary is **1-10s** (outside = failure); **recommended range 3-8s** (the empirical window of generation-model quality + editing rhythm; lint doesn't check it). Over 10s you must split the scene.
- **Runnable script self-check**: `examples/` is the bundled sample (two-shot demo showing how to write the 10-line fields and continuity). Run it once to confirm environment and format are fine:

```bash
python3 scripts/scene_lint.py examples/
```

Expected output: `ALL OK`, exit code 0. Use the workspace `storyboard/` directory for your real storyboard.
- Does an identically-named scene file already exist in the output directory `storyboard/`? If so, first ask whether to overwrite (prevents accidental deletion of a confirmed draft).

## Tacit Knowledge (Film Grammar: Making Different Scenes Actually Cut Together)

### 1. The 180-Degree Line (Axis): The Lifeline of Spatial Orientation Across the Film

In a two-person scene / chase, the camera must stay on the **same side** of the line connecting the two characters. Crossing the axis (shooting from the other side) collapses the viewer's sense of space — A was clearly on the left of the frame, and in the next shot is suddenly on the right, so the viewer thinks the space changed.

**There are only two legal ways to cross the axis**: cut in a neutral head-on / empty-space shot (front close-up / pure environment empty shot) as a transition, or use a moving shot to cross the axis on the spot. In the storyboard file this shows up as: adjacent scenes' camera moves and character facing directions must not "swap left and right" without a transition.

### 2. The 30-Degree Rule: Avoid Jump Cuts

If two adjacent shots have **less than 30 degrees of camera-position change and similar shot sizes**, cutting them together looks like the frame "jumped" (same space, same position, but the person flickered). Two ways to avoid it: move the camera at least 30 degrees, or change shot size across a tier.

### 3. Eyeline Match: The #1 Failure Mode in AI Generation

A looks screen-right -> B should look screen-left (their gazes meet off-screen). **A high-frequency AI failure mode**: both characters look to the same side (like staring in one direction), or both stare at the lens (a two-hander becomes two people each delivering a soliloquy). When writing prompts you must explicitly write the eyeline direction (`looking screen-left` / `gazing off-screen right`); don't just say "they're making eye contact".

### 4. Match-on-Action: The Preferred Way to Suture the Cut Point

Cut a continuous action **in the middle** (hand halfway extended, body halfway turned), and let the next shot finish it — the viewer's eye is carried by the action and misses the cut. This is especially important for AI generation: a single clip is generally <=10s, so long actions must be split; **cut the split point in the middle of the action**, not "after the action finishes".

### 5. Establishing Shot: Tell "Where This Is" First in a New Scene

When entering a new scene, first give a wide environmental master (far, broad), then go to the character's close-up. Without an establishing shot, viewers spend attention guessing spatial relationships instead of following the plot.

### 6. Shot-Size Gradient: Adjacent Shots Must Span At Least One Tier

Wide -> full -> medium -> close -> extreme close (or reverse), progressing; two adjacent shots with the same size and same camera position = a jump cut (see Rule 2). Across the whole film use **at least 3 shot sizes** (empirical threshold: this group's operationalization of "avoid visual hypnosis", not an industry number; lint doesn't check it — it's a manual review item).

### 7. Three Extra Constraints for AI Generation

1. **The continuity table = the generation model's prompt-prefix vocabulary**: it's not just a documentation discipline. At generation time, each scene's prompt must repeat the character's appearance features (hairstyle/glasses/outfit) verbatim; the table is the copy source.
2. **Single-clip 3-8s is the usable-quality window**: not a film-grammar requirement, but an engineering constraint of current generation models (long clips drift easily).
3. **Match-on-action is the default split technique** (Rule 4); the split point must be in the middle of an action.

## Red Lines (Hard Bans)

1. **Forbidden to draw fake storyboard images with code/SVG as filler**: this skill only produces prompt scripts; storyboard images must be generated by an image model. Drawing a "diagram" and passing it off as a storyboard image is fabricating the deliverable.
2. **Don't invent visual settings the user didn't give**: once character appearance, wardrobe, and props are locked in the continuity table, later scenes may only reference them; if a change is needed, ask the user first — don't "optimize" on your own.
3. **The beat-sheet total duration must equal the total duration**: don't pad duration to fit scenes, and don't cram in scenes to fit duration.
4. **Don't overstep to generate video/images**: the deliverable is prompt scripts and the constraint table.
5. **Don't treat `ALL OK` as proof of quality**: lint is a shape check (see Honest Disclosure 1) — at delivery you must state explicitly that the content layer was not machine-checked.

## Honest Disclosure (scene_lint.py's Actual Boundaries, Probed 2026-09-22)

1. **Lint is a shape check, not a content check**: as long as the 9 required fields satisfy "`field name: any non-empty value`", it passes — tested by filling **all field values with the letter `x`**, and lint still reports `ALL OK`. Content quality, grammar correctness, and creativity are all outside machine verification.
2. **Lint does not check whether `continuity.md` and `beat-sheet.md` exist**: tested a directory with only scene files (no those two files) and it still reported `ALL OK`.
3. **This revision**: the old docs claimed the structure formula was "9 fields" but the formula actually listed 10 lines. The accurate statement is — **lint checks 9 fields (not including `continuity`)**; `continuity` is this skill's delivery requirement, checked manually.
4. **Unparseable values like `duration: x` skip the duration check** (if the regex finds no number it doesn't check) — it's not an error.
5. **Hard duration boundary 1-10s** (outside = FAIL); **recommended 3-8s is NOT checked by lint**.
6. **Lint checks none of**: shot-size gradient, eyeline direction, axis (180-degree), continuity-table consistency — i.e., tacit knowledge 1-7 here is entirely on human/review checking.
7. Exit codes: 0 = all pass; 1 = problems (listed one by one) or directory doesn't exist.

## Workflow

### Step 0: Determine the Output Directory

```bash
mkdir -p storyboard/
```

Expected: `storyboard/` ready, and all later scene-NN.md files land in this directory.
If it fails: `mkdir` reports a permission/path error -> confirm a writable directory with the user and switch to that path, and tell the user how the final path differs from the commands later in this doc.
**Pure conversational mode (can't run shell)**: treat `storyboard/` as a logical path convention — just produce each file's content directly and say "please save as `scene-NN.md`"; **don't abandon the task just because you can't create the directory**.

### Step 1: Produce the Beat Sheet

Output into the output directory (`storyboard/`), named beat-sheet.md. Don't write prompts yet; lock the rhythm first. One beat per row:

```markdown
| # | Time | Beat Function | One-Line Frame | Sound |
|---|------|----------|-----------|------|
| 1 | 0-3s | hook | rainy neon street, camera pushes toward the person under the umbrella | rain fade-in |
```

Beat functions use only five: `hook` / `setup` / `beat` / `twist` / `cta`. A typical 30s rhythm = hook 3s + setup 5s + beat x3 + twist 5s + cta 2s.
Expected: beat-sheet total = total duration; otherwise return to this step and re-cut.
If it fails: concept can't be told -> suggest "cut the concept" or "raise the duration"; ask the user to pick one; don't add duration on your own.

### Step 2: Lock the Continuity Table First (Before Writing Any Scene)

Output into the output directory (`storyboard/`), named continuity.md:

```markdown
| Dimension | Locked Value | Source Scene |
|------|--------|----------|
| Character | Xiaoyu, short-haired woman in black | all |
| Wardrobe | black hoodie, white shoes | set in scene-01 |
| Key prop | blue lighter | appears scene-02 -> reappears scene-04 |
| Location | rainy-night convenience-store doorway | scene-01/02 |
| Aspect ratio | 9:16 | all |
| Color grade | teal-orange contrast, night highlight bloom | all |
| Eyeline baseline | walks on the left of the main view -> looks screen-right | set in scene-01 |
```

Every dimension must have a "source scene" — later scenes may only reference locked values; scene-05 isn't allowed to suddenly change outfits.
Expected: the continuity table is **finalized before scene prompts**; any scene prompt conflicting with the table triggers a rewrite of that scene.
If it fails: a dimension has no "source scene" (e.g., a prop appears only at the end with nobody locking it) -> go back to Step 1 and add the prop's introduction beat in the beat sheet, then return to this step to fill the table; don't write it directly into a scene.

### Step 3: Produce Prompt Pairs Per Scene

For each scene, output two files (two-digit numbering, starting from 01):

- `scene-01.md` (stored in the output directory `storyboard/`) — the scene prompt script (structure per the formula in the next section)
- The scene's image-board description block (if the user has an image-generation tool, generate scene-01.png per this block and save it in the same directory; this skill only produces prompts, not images — forbidden to draw fake storyboard images with code/SVG as filler)

When writing each scene, check tacit knowledge 1-7 and the continuity table; arrange adjacent scenes' camera position / shot size per the 30-degree rule (Rule 2) and shot-size gradient (Rule 6).

### Step 4: Run Lint

```bash
python3 scripts/scene_lint.py storyboard/
```

Expected: `ALL OK`. Non-0 exit codes are fixed per the output, one by one.
If it fails: reports "non-contiguous scene numbering" -> renumber the files; "missing field" -> add that field per the "scene-file structure formula" below; "duration outside the safe zone" -> split the scene or adjust to 3-8s and rerun. Repeated failures -> report the specific filename and missing field to the user.

### Step 5: Manual Grammar Review + Delivery

Lint only guards the shape (Honest Disclosure 1); before delivery you must go through the grammar items of the "built-in verification steps" one by one. Output to the user: beat sheet + continuity table + scene-file list + **grammar-review conclusion**.
If it fails: the list disagrees with files on disk -> re-check per the actual `ls storyboard/` results; don't report a list from memory.

## Scene-File Structure Formula (scene-XX.md)

```markdown
# Scene NN —— <one-line summary>
- duration: <Ns>  aspect: <ratio>  shot size: <wide/full/medium/close/insert>
- frame: <subject> + <action> + <environment> (one complete sentence, <=40 words)
- camera move: <push/pull/pan/truck/follow/static> + <speed>
- lighting: <time of day + light source + contrast>
- sound: <dialogue/TTS text | ambient SFX | BGM mood>
- video prompt: <English prompt directly feedable to a generation model, incl. duration and aspect ratio>
- transition: exit transition <hard cut/J-cut/match cut/dissolve>
- continuity: reference the continuity table row <copy the value verbatim>
```

10 field lines total; lint machine-checks 9 (not including `continuity`, see Honest Disclosure 3); `continuity` is checked manually.

## Parameter Quick Reference

| Parameter | Value | Notes |
|------|------|------|
| Per-scene duration | Hard boundary 1-10s; recommended 3-8s | Generation models generally cap a clip at <=10s; longer must split scenes |
| Scene count | duration / 5s | 30s -> 5-7 scenes (empirical) |
| Shot-size gradient | >=3 sizes across the film (empirical threshold) | Same size all through = visual hypnosis; lint doesn't check but review will reject |
| Adjacent-shot difference | Camera >30 degrees or shot size across a tier | Otherwise it cuts as a jump cut (tacit knowledge 2) |

## Built-in Verification Steps (Check Each Before Delivery)

**Shape items (lint-checkable)**
- [ ] Scene numbers sequential, starting from 01
- [ ] Each scene has all 9 machine-checked fields; durations all within 1-10s
- [ ] `scene_lint.py` exit code 0

**Grammar items (manual; lint doesn't check)**
- [ ] **Axis**: two-handers/chases stay on the same side throughout, no un-transitioned axis crossing
- [ ] **Jump cut**: adjacent shots' camera position changes >30 degrees or shot size spans a tier
- [ ] **Eyeline match**: two-handers' eyelines point opposite ways and meet (write left/right explicitly)
- [ ] **Match-on-action**: cross-scene continuous actions cut mid-action, not after completion
- [ ] **Establishing shot**: every new scene has environmental orientation
- [ ] **Shot-size gradient**: >=3 sizes across the film (empirical threshold), no single-size slog
- [ ] **Continuity consistency**: every scene's `frame` and `video prompt` match continuity.md value by value (appearance features especially carried through)
- [ ] **Beat alignment**: scenes' time splits match beat-sheet.md

## Failure Remediation Table

| Symptom | Cause | Remedy |
|------|------|------|
| Beat total != total duration | Rough splitting | Re-cut at 1s granularity; set hook and cta ends first |
| Face changes between scenes | Continuity table filled in late | Rebuild: lock the table before writing scenes (Step 2 before Step 3) |
| Prompt exceeds the model's duration limit | Single scene >10s | Split in two, **cut mid-action** (tacit knowledge 4), transition with a match cut |
| Two-hander both look the same direction | Eyeline not locked down | Add `looking screen-right` / `screen-left`; rewrite both shots per eyeline match |
| Cuts "jump" | Same camera position and shot size adjacent | Change camera position or shot size per the 30-degree rule |
| Viewer says "it made me dizzy" | Axis crossing without transition | Insert an on-axis neutral shot or a moving cross-axis shot |
| User wants storyboard images, not prompts | Misunderstanding | Still produce .md (prompts are the amplifier for images); explain the purpose |
| Lint says ALL OK but content is poor | Lint is a shape check | Manually review per the grammar items of "built-in verification steps" (Honest Disclosure 1) |

## Delivery Standard

- `storyboard/scene-01.md ... scene-NN.md`, NN sequential with no gaps
- Each file contains the 10 field lines above (9 machine-checked + `continuity`); missing any = not qualified
- Beat sheet + continuity table delivered along (saved as `beat-sheet.md` and `continuity.md` in the output directory)
- `scene_lint.py` exit code 0
- **Grammar-review conclusion delivered along** (conclusions for each of the 8 grammar items in "built-in verification steps"; no omissions)
