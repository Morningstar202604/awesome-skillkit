# Methodology sources and acknowledgements

> This skill's storyboard methodology was not invented out of thin air. The following open-source
> projects provided battle-tested structure and discipline; we distilled their **methodological skeleton**
> (beat-sheet-first, continuity constraint tables, per-scene paired output, contract-driven output) and
> rewrote it as a Chinese-language workflow combined with this repo's SKILL-STANDARD-v2 "machine-first
> ten commandments." We did not copy any original text; for the originals, please visit the repos below.

## Merged to this repo's standards

When the above methodology entered this repo, three kinds of adaptation were made:

1. **Commandment-ized**: every step was supplemented with an "expected result + failure branch" (SKILL-STANDARD-v2 §3, commandment 2);
2. **Deterministic-ized**: scene files are given a fixed 10-line structural formula rather than free form;
3. **Verifiable-ized**: a new `scene_lint.py` machine check was added (naming continuity + presence of 9 fields + duration bounds).
   **Correction (2026-09-22)**: an early phrasing said "demote human review to a script gate + humans only look at creativity"—this was an
   **over-promise**. Probe measurements (see below) prove the lint only does shape checks; it looks at neither content nor shot grammar.
   The accurate framing is: **the script guards the gate on shape; humans guard the gate on content and grammar**.

## Shot-grammar sources (added in batch 4, 2026-09-22)

The shot grammar in SKILL.md tacit knowledge 1–7 is the standard teaching line used across the film
industry; it was written in after this round of online verification:

| Tacit knowledge | Content | Degree of trust |
|---|---|---|
| 180° line (axis) | Keep shooting from the same side in a two-person scene; crossing the axis requires inserting a neutral shot or a move across it | Trusted: a universal film-production rule |
| 30° rule | Adjacent shots with <30° camera change and similar shot size → jump-cut feel | Trusted: the same universal rule of thumb |
| Eyeline match | A looks screen-right → B looks screen-left | Trusted: a universal editing-grammar rule |
| Action match | Cut mid-continuous motion to hide the edit point | Trusted: same as above |
| Establishing shot | Open a new scene by showing the full environment | Trusted: same as above |
| Shot-size gradient | Adjacent shots cross a size tier; ≥3 shot sizes across the whole film | Half-trusted: "cross a tier" is a universal rule; "≥3" is this group's operationalization of the "avoid visual hypnosis" heuristic, not an industry number |
| Usable single-segment 3–8s range | — | **An engineering constraint, not grammar**: it comes from the generation model's per-segment duration and drift characteristics, and is explicitly marked in SKILL.md |
| Continuity table = prompt prefix vocabulary | — | This group's design criterion (hooking the constraint table to the generation action) |

**Not trusted**: any unverified "X% drop-off after 3 seconds" / "Y% completion-rate lift" numbers are
not written in, period.

## lint probe measurement record (2026-09-22)

Boundary probing of `scene_lint.py` using constructed samples; results below are all reproducible:

| Probe | Input | Result | Conclusion |
|---|---|---|---|
| Shape-check boundary | 2 scene files, **all field values being the letter `x`** | `ALL OK`, rc=0 | The lint only checks "field name: non-empty value," not content |
| Duration out of range | duration field: 99s | `FAIL: DURATION`, rc=1 | The 1–10s hard bound works |
| Duration unparseable | duration field: x | Skips duration check (no error) | If the regex finds no number, it skips the check |
| Constraint-table presence | No `continuity.md` / `beat-sheet.md` in the directory | Still `ALL OK` | The existence of the two files is not in the check scope |
| Unchecked items | Shot-size gradient / eyeline / axis / continuity consistency | Not in REQUIRED_FIELDS | Relies entirely on manual checking (SKILL.md's built-in validation-step grammar items) |

> Purpose of the record: let SKILL.md's "honesty statement" be independently re-checkable; whenever
> any item disagrees with the code, the code wins and the docs are revised back.
