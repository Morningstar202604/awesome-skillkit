## §0 Actual correspondence with `simulation.py`

Behavior of `simulation.py`'s `--monte-carlo` mode (confirmed by reading the source):
- Sampling uses the stdlib `random.gauss(mu, sigma)`, **not** numpy.
- Output fields: `n` / `mean` / `std` / `p50` / `p95` (the key name is generated by `f"p{int(quantile*100)}"`, default quantile=0.95) / `p_exceed_threshold` / `min` / `max` / `threshold` / `status`.
  Note: the SKILL.md example writes `p_exceed`, but the **actual key is `p_exceed_threshold`**; the same feature in model-solver returns the key `p_exceed`, so the two are inconsistent—when writing downstream code, read the value using the actual key.
- `std` uses `statistics.stdev`, i.e. the **sample standard deviation (ddof=1)**.
- Quantiles are taken by sorting and indexing at `int(n*quantile)`, which is an **empirical quantile** (no interpolation), so it may differ slightly from `np.quantile`'s linear-interpolation result.
- **The script has no `--seed` argument**, so every run gives different results → when you need reproducibility, use the wrapping approach in §6, or switch to the numpy version (§3).
- `param_scan` and `sensitivity` currently only output a "plan" (`note: run model-solver for actual result`) and do not actually call the model; to get real numbers you must feed each parameter point into model-solver yourself.

## §1 Basic idea: write the quantity of interest as an expectation

Three steps: ① write the quantity θ as `θ = E[g(X)]`; ② draw n independent samples from X's distribution; ③ estimate θ by the sample mean `θ̂ = (1/n)Σ g(Xᵢ)`.
- Definite integrals, probabilities, expectations, quantiles, and risk metrics (VaR / probability of exceeding a threshold) can all be written in this form.
- Example: π/4 = P(point falls inside the unit circle) = E[1{x²+y² ≤ 1}], x,y ~ U(0,1).

## §2 Law of large numbers and the 1/√n convergence rate

- Law of large numbers: as n → ∞, θ̂ → θ (almost surely / in probability).
- The central limit theorem gives the error scale: **standard error SE = σ/√n** (σ is the standard deviation of g(X), estimated by the sample std s).
- The meaning of 1/√n (the single most important point): **a 10× improvement in precision needs 100× more samples**; halving the error needs 4× more samples. Buying precision by piling up samples quickly becomes uneconomical → prefer the variance-reduction techniques in §5.
- Relative-error view (rare events): when estimating a probability p, the relative error ≈ `1/√(n·p)`. The smaller p is, the more samples you need: for p = 1e-5 and a desired relative error of 10%, the order of magnitude is n ≈ 1/(p·0.01) = 1e7 runs (**this is an order-of-magnitude statement, not a guarantee**). This is why tail risk calls for importance sampling (§5).

## §3 Runnable example: estimation with standard error and confidence interval

```python
import numpy as np

rng = np.random.default_rng(20260914)      # fixed seed → reproducible
n = 100_000
x = rng.normal(0, 1, size=n)
g = (x > 2).astype(float)                  # indicator function: estimate P(X > 2)

mean = g.mean()
se = g.std(ddof=1) / np.sqrt(n)            # ddof=1: sample standard deviation
print(f"p_hat={mean:.6f}  se={se:.6f}  CI95=[{mean-1.96*se:.6f}, {mean+1.96*se:.6f}]")
```
Measured output on this machine (seed=20260914, n=100000):
`p_hat=0.022120  se=0.000465  CI95=[0.021208, 0.023032]`
Criterion: the theoretical value P(X>2) ≈ 0.0228 falls inside the CI → the result is credible; if the true value is outside the CI, first check whether the samples are independent, whether the seed was reused, and whether g is written correctly.
`1.96` is the commonly used approximation of the 95% quantile of the normal distribution; the CI formula relies on the central limit theorem, and the rule of thumb for proportion estimation is that both `n·p` and `n·(1-p)` are at least 10 (**VERIFY BEFORE USE**: for rare events the normal approximation breaks down—use a larger sample or an exact method).

## §4 Is the sample size enough: criteria and back-of-envelope formulas

Do not pick n by gut feeling; back it out from the target precision:
```
Target: relative error ≤ ε (e.g. ε = 0.05, i.e. 5%)
n ≈ (1.96 · s / (ε · |θ̂|))²
```
First use a small sample (e.g. n₀ = 1000) to estimate s and θ̂, plug them in to compute n, then run the full batch, and finally re-check with the full-batch s.

Measured example (estimating P(X>2), taking ε = 0.05): after estimating s and θ̂ on a small sample, the computed `n ≈ 6.5e4`, consistent with the relative error obtained in §3 using 1e5 (se/mean ≈ 2.1%).

Systematic criteria:
1. Fix the seed and run once with n and once with 4n → if the difference between the two estimates is far smaller than their respective SEs, you have entered the stable region.
2. When reporting, you **must also give the SE or CI**; a Monte Carlo result that only reports `mean` cannot be judged for credibility.
3. If the relative error misses the target and the sample is already large → switch to variance reduction (§5) instead of adding more samples.

## §5 Variance reduction (four ideas and their applicable conditions)

### 5.1 Antithetic Variates
Idea: pair each sample `u` with a "mirror" sample (for the standard normal use `-u`; for the uniform use `1-u`), and take the average of `g(u)` and `g(mirror)`.
Applicable: when `g` is **monotonic** in the input, the two estimates are negatively correlated and the variance drops.
```python
m = 100_000
u = rng.standard_normal(m)
pair = (np.exp(u) + np.exp(-u)) / 2                  # estimate E[e^X], true value e^0.5=1.648721
print(pair.mean(), pair.std(ddof=1) / np.sqrt(m))    # SE must be computed from the paired averages, not from the 2m raw values
```
Measured: `anti mean=1.646170 se=3.80e-03`; ordinary sampling at the same size gives `mean=1.649599 se=4.79e-03` → SE reduced by about 21%.
Pitfall: the SE must be computed from the sequence of **paired averages** (`pair.std(ddof=1)/sqrt(m)`); directly applying `std/sqrt(2m)` to the 2m raw values is wrong because the samples are not independent (in testing it leads to the erroneous conclusion that "there is no benefit").
Not applicable: g is non-monotonic (e.g. the indicator 1{x>2} shows negligible measured benefit).

### 5.2 Control Variates
Idea: find a quantity c that is strongly correlated with g and whose **expectation is known** (e.g. c = X, E[X] = 0), replace g with `g - β(c - E[c])`, taking β = `Cov(g,c)/Var(c)` (estimable from the sample).
```python
z = rng.standard_normal(200_000)
g, c = np.exp(z), z
cov = np.cov(g, c, ddof=1)
beta = cov[0, 1] / cov[1, 1]
adj = g - beta * (c - 0.0)
print(adj.mean(), adj.std(ddof=1) / np.sqrt(len(g)))
```
Measured: `beta=1.6483`, and `se` dropped from 4.78e-03 to 3.05e-03 (about 36% reduction).
Applicable condition: you can find a control whose expectation is **analytically known** and which is highly correlated. Estimating β from the sample introduces a slight bias; use it cautiously when the sample is very small.

### 5.3 Importance Sampling
Idea: sample from a different distribution q (concentrating sampling on the "important region", e.g. the tail), and weight by the likelihood ratio `w = p(x)/q(x)`: `θ̂ = mean(w · g(x))`.
Applicable: rare events / tail probabilities.
```python
from scipy.stats import norm
n, shift = 200_000, 4.0
y = rng.standard_normal(n) + shift          # sample from N(shift, 1)
w = np.exp(-shift * y + 0.5 * shift ** 2)   # likelihood ratio f0(y)/f1(y)
est = (w * (y > 4)).mean()                  # estimate P(X > 4)
se = (w * (y > 4)).std(ddof=1) / np.sqrt(n)
print(f"est={est:.3e}  se={se:.1e}  rel={se/est*100:.2f}%")
```
Measured (multiple shifts / seeds): with `shift=3/4/5` and `seed=11/12`, the estimates range 3.15e-5 ~ 3.19e-5, the true value is 3.167e-5, and the relative error is **0.47% ~ 0.68%**; naive sampling at the same n only hit 9 times (estimate 4.5e-5, relative error about **40%**).
Pitfall (must check): weights can degenerate. In this example, `max(w)/mean(w)` was on the order of 1e3 ~ 1e5—strongly right-skewed weights. The check: re-run several times with different shifts (3/4/5) and different seeds; the estimates should be stable (they are in this example); if the estimates swing wildly after changing parameters, the variance is in fact large and the conclusion is not credible.

### 5.4 Stratified Sampling
Idea: stratify the input space (e.g. cut into k segments by quantiles), independently draw n/k samples per stratum, then weight and aggregate.
Applicable: low-dimensional inputs (the number of strata explodes at high dimensions) and when you know the probability mass of each stratum.
Implementation notes: the per-stratum sample count can be allocated by stratum variance (draw more from high-variance strata), but the stratum probability weights must be normalized correctly.

## §6 Random numbers and reproducibility

- Prefer the new numpy API: `rng = np.random.default_rng(seed)`; avoid the global `np.random.seed()` (it pollutes other libraries).
- For stdlib `random`, use `random.seed(seed)`; `simulation.py` uses stdlib `random` and **does not expose a seed → two runs give different results**. A temporary workaround for reproducibility:
```bash
python3 -c "import random, runpy, sys; random.seed(42); sys.argv=['simulation.py','--monte-carlo','--n','10000']; runpy.run_path('simulation.py', run_name='__main__')"
```
(A more robust approach is to add a `--seed` argument to the script and call `random.seed(args.seed)`.)
- Parallel / multiprocessing: do not start multiple child processes with the same seed (they'll produce the same stream). Use `np.random.SeedSequence(seed).spawn(k)` to give each child process an independent stream.
- Record the three essentials: **seed + library versions + code version**. Missing any one makes the result unreproducible.
- State the seed in the report; when comparing two schemes, use the **same seed and the same batch of random numbers** (paired comparison significantly reduces the variance of the comparison).

## §7 Checklist and common pitfalls

- [ ] The quantity of interest is written in the form `E[g(X)]`
- [ ] A fixed seed is used and stated in the report
- [ ] The output includes the SE or CI, not just the mean
- [ ] The sample size is back-calculated per §4, not picked as 10000 on a whim
- [ ] Stability was re-checked with n and 4n
- [ ] Rare events prefer importance sampling, and weight degeneration was checked (re-run with a different shift / seed)
- [ ] Quantile-type metrics (`p95` etc.) have larger error than the mean; the sample size should be raised accordingly
- [ ] Downstream reads use the script's **actual key name** (`p_exceed_threshold`, not `p_exceed`)

Common pitfalls: ① reusing the same rng object's stream makes two experiments "coincidentally" correlated; ② mixing up the sample std `ddof=1` with the population std (the SE formula requires estimating σ with the sample std; the difference is negligible at large n); ③ using `std/sqrt(n)` to estimate the SE of correlated samples (e.g. antithetic pairs, MCMC chains) severely underestimates the error.
