## 一、营销日历：节奏设计（节点 vs 日常）

**策略判断**：CLI 工具用户具有**“反营销”**属性，抵触硬广，但欢迎“真干货”。因此采用**“日常型 + 微型节点”**混合节奏，而非大型促销节点。

| 阶段 | 时间 | 节点/动作 | 主渠道 | 核心目标 | 素材需求 |
|------|------|-----------|--------|----------|----------|
| **预热期** | T-7 至 T-1 | **“暗号”泄露**：在 Hacker News / 少数派 / 即刻发布“我在做一个反人性的 CLI 工具” | 社区（微博/即刻/HN） | 种子用户收集、饥饿营销 | 1 张概念图 + 300 字“为什么做”的技术博客 |
| **爆发期** | T 日至 T+3 | **正式版上线**：GitHub Repo 开放 + Twitter/X 技术大 V 联动 | GitHub + Twitter/X | 下载量 / GitHub Star | 演示 GIF 视频（15s）、README 文档、对比表格 |
| **长尾期** | T+4 至 T+28 | **场景化种草**：每周一个具体痛点解决方案（如“如何把 5 分钟任务变成 10 秒”） | 小红书 + 知乎 + 邮件列表 | 留存 / 复购 / 口碑转介绍 | 3 篇深度图文（痛点场景化）、2 个短视频 |
| **复盘期** | T+29 至 T+30 | 数据清洗与 A/B 结果回收 | 内部 | 优化下一轮策略 | 数据报表 |

> **关键纪律**：预热期 ≥ 7 天，确保种子用户在爆发期形成初始声量，避免“上线即沉默”。

| 渠道类型 | 渠道名称 | 角色 | 内容形态 | 转化路径 |
|----------|----------|------|----------|----------|
| **种草（拉新认知）** | 小红书 | **“程序员逆袭”场景化** | 图文/视频：展示“别人加班 3 小时，我 10 秒搞定”的对比场景 | 评论区置顶 GitHub 链接 |

## 三、A/B 变体对设计（单变量纪律）

**测试前提**：仅针对**落地页（Landing Page）标题**与**CTA 按钮**进行测试，其他元素保持不变。

### 对 1【标题钩子】
*   **假设**：数字量化效果 > 抽象价值主张（程序员更信数据）
*   **A 组**："**节省 80% 时间**：你的 CLI 效率倍增器"
*   **B 组**："**告别重复劳动**：重新定义开发者工作流"
*   **差异维度**：标题前半部分（数字承诺 vs 价值描述）

### 对 2【CTA 措辞】
*   **假设**：损失厌恶 > 行动指令（“别错过”比“点击”更具紧迫感）
*   **A 组**：**"立即锁定早期版本"**（限时/限量暗示）
*   **B 组**：**"开始使用工具"**（直接行动）
*   **差异维度**：CTA 按钮文字

> **关键纪律**：
> 1. 每对变体只改一个维度。
> 2. 同时测试 ≤ 2 对（标题 + CTA），避免多变量污染。
> 3. 测试周期至少 7 天，确保统计显著性。

## 四、衡量指标（KPIs）

| 层级 | 指标 | 目标（参考值） | 归因渠道 |

## 五、失败处置预判

| 现象 | 可能原因 | 处置 |
|------|----------|------|
| GitHub Star 高但下载低 | README 缺乏 Quick Start 或安装复杂 | 优化文档，增加“一键安装”脚本 |
| 小红书爆但知乎沉默 | 内容过于浅显，缺乏技术深度 | 知乎投放技术大 V 背书文章 |
| 点击高但激活低 | CTA 与实际产品体验不符（标题党） | 检查落地页加载速度与首屏体验 |
| A/B 测试无显著差异 | 样本量不足或测试时间太短 | 延长测试周期，扩大流量入口 |
