# CLI 效率工具上线 Campaign 设计

> **基础文案（由 product-copywriter 产出，假设为）：**
> **「TidyCLI」** —— 一行命令清理项目目录中废弃依赖、重复配置和冗余文件。`tidy clean --project`，30 秒还你清爽的 codebase。核心卖点：智能识别、零误删、支持 Git 工作区。

---

## 一、战役目标

| 目标 | 权重 |
|------|------|
| 冲销量/下载量 | 70%（工具类产品首月安装量决定口碑裂变） |
| 打认知 | 20%（程序员社区信任需要时间积累） |
| 清库存 | 不适用 |

**档期**：假设 6 周内上线，避开双 11 等电商节点，选择**技术活动节点**（见下）。

---

## 二、营销日历（节点型节奏）

| 日期 | 节点/阶段 | 主渠道 | 动作 | 素材需求 |
|------|-----------|--------|------|----------|
| D-14 ~ D-7 | **预热期**（种草） | 技术社区（V2EX、即刻、Twitter/X） | 开发者痛点内容：「你的项目目录有几层垃圾？」悬念式推文 + 产品截图流 | 3 篇图文长帖、5 条短视频（60 秒内展示清理前后对比） |
| D-7 ~ D-1 | **蓄水期**（意向收集） | 邮件列表 + 技术博客 | 开放早期体验名额，收集开发者反馈 | 落地页、报名表单 |
| D-Day | **爆发期**（转化） | GitHub Release + Hacker News + V2EX 置顶帖 | 正式发布 + 限时免费/早鸟价 | README.md、API 文档、GitHub Actions CI badge |
| D+1 ~ D+7 | **返场期**（口碑扩散） | 社群（Discord/微信群）+ 知乎回答 | 用户案例分享、问答互动、激励推荐 | 用户证言卡片、推荐有礼机制 |
| D+8 ~ D+30 | **日常期**（持续渗透） | 技术播客 + Newsletter + Reddit r/commandline | 每周 1 篇深度内容，维持搜索流量 | 教程文章、FAQ 文档 |

> **纪律**：节点型战役预热段 ≥7 天，确保 GitHub Issue 和 HN 点选有足够发酵时间。

---

## 三、渠道矩阵（一渠道一角色）

| 渠道 | 角色 | 内容形态 | 关键指标 |
|------|------|----------|----------|
| **GitHub Releases** | 核心转化阵地 | README、安装指令、CI Badge | 下载量、Stars、Issues 解决率 |
| **V2EX / 即刻 / 掘金** | 种草拉新 | 场景化图文：「30 秒清理 10 年旧项目」 | 点击率、报名转化率 |
| **Hacker News** | 信任背书 | 技术深度帖（非软文），展示实现细节 | 点选数、评论质量、引用量 |
| **知乎 / Reddit r/commandline** | 长期搜索承接 | 问答形式：「如何自动化清理 node_modules？」 | SEO 排名、回答点赞、引流链接点击 |
| **技术播客（如 V2EX 周边/即刻电台）** | 人格化传播 | 访谈式内容，讲产品背后工程故事 | 播放量、听众反馈 |
| **Newsletter（Substack/Beehiiv）** | 私域复购/转介绍 | 每周工具推荐 + 使用技巧 | 打开率、退订率、推荐码使用量 |
| **社群（Discord/微信）** | 即时反馈与口碑 | 用户互助、bug 报告、Feature Request | 活跃度、NPS、转介绍率 |

> **纪律**：同一素材不在不同渠道直发——V2EX 适合短平快痛点帖，HN 需要技术深度，知乎要回答具体问题，播客讲故事。**适配交给 channel-adapter**。

## 四、A/B 变体对（单变量纪律）

### 对 1【标题钩子】
**假设**：数字钩 > 悬念钩（程序员偏好具体数字而非模糊描述）

| 变体 | 内容 |
|------|------|
| A | 「30 秒清理 10 年旧项目：一个 CLI 的自救指南」 |
| B | 「为什么你的项目目录越来越慢？答案可能在一行命令里」 |

**测试渠道**：V2EX / 即刻首发帖标题  
**衡量**：点击率（CTR）

---

### 对 2【CTA 措辞】
**假设**：损失厌恶 > 行动指令（「别让你的项目继续臃肿」比「立即体验」更能触发行动）

| 变体 | 内容 |
|------|------|
| A | 「别等项目跑不动再清理 → 立即体验 TidyCLI」 |
| B | 「点击了解 TidyCLI，30 秒还你清爽 codebase」 |

**测试渠道**：落地页 / 邮件 CTA 按钮  
**衡量**：转化率（CVR）

---

> **纪律**：同时只跑这 2 对变体，每对独立流量桶，避免互相污染。测完赢家写回基础文案，下一轮基于新基线迭代。
