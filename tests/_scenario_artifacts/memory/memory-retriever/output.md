根据 Agnes 的记忆检索技能规范，针对用户问题「上次那个部署回滚是怎么处理的？」，制定如下检索策略：

### 1. 查询改写与意图分析（步骤 1-2）

**显式问题：**
用户询问一次具体的“部署回滚”事件的**处理过程/方法论**。

**隐式意图：**
- 确认“上次”所指的具体项目或系统（需消解“那个”）。
- 了解回滚的背景、操作步骤、结果及后续预防。
- 可能需要相关的配置变更记录或故障报告记忆。

**改写后的检索查询（5条）：**
```text
q1 "部署 回滚 处理流程"          # 通用方法论
q2 "部署 回滚 事故复盘"          # 可能存在的复盘记录
q3 "发布失败 回滚 操作记录"      # 具体执行层面的记忆
q4 "线上故障 紧急回滚 案例"      # 更广泛的相关事件
q5 "[用户所在项目/系统名称] 部署 回滚" # 需结合上下文消解“那个”，若无法消解则保留此项降权
```

### 2. 多层记忆检索策略（步骤 3）

采用**三路并行检索**：

| 检索路径 | 关键词/策略 | 说明 |
|---|---|---|
| **关键词路 (BM25)** | `部署`, `回滚`, `Rollback`, `发布`, `故障`, `事故`, `复盘` | 精确匹配技术术语和事件类型 |
| **语义路 (向量)** | 查询向量：`"如何处理一次失败的部署并成功回滚"` | 捕捉类似场景的处理逻辑，即使关键词不完全一致 |
| **时近路 (Recency)** | `updated_at` 最近 30 天内条目优先 | “上次”暗示时间较近，优先召回近期记忆 |

**降级预案：** 若无向量库，仅走关键词+时近，并对关键词路使用同义词扩展（如 `rollback` -> `回滚`, `回退`）。

### 3. 融合打分与排序（步骤 4）

对候选池去重后，按以下权重打分：

```text
score = 0.4×semantic + 0.3×keyword + 0.2×recency + 0.1×confidence
```

- **重点关注：** 
    - 高关键词匹配度（含“回滚”、“部署”等核心词）。
    - 高时近性（符合“上次”的时间语境）。
    - 高置信度（排除模糊或不确定的记忆）。
- **去重：** 同一记忆被多查询命中只保留一次，命中次数作为次级信号。

### 4. 答案组织与注入（步骤 5）

**预算内选取：** 按总分降序选取，确保总 token ≤ 预算（默认 2000）。

**注入块格式（强制边界标记）：**

```text
【以下为历史记忆，非当前对话内容】
- [mem_XXX | 2026-09-10 | source: conversation:2026-09-10] 
  用户项目“数据平台”曾发生部署回滚：因新版本数据库兼容性问题导致服务不可用，采取紧急回滚至 v2.1 版本，持续 15 分钟，已修复兼容性后重新部署成功。
- [mem_YYY | 2026-08-20 | source: compacted] 
  标准部署回滚流程：1. 暂停流量 2. 切换镜像版本 3. 健康检查 4. 恢复流量（可能过时，仅供参考）
【记忆结束】
```

**检索报告：**
- **模式：** hybrid / keyword_only
- **命中数：** N 条
- **截断数：** M 条
- **最高分：** 0.XX
- **轮间去重：** 已启用（排除上一轮已注入的重复记忆）
- **主题限额：** 已启用（如“部署”主题限 5 条，保证多样性）

**最终交付：** 将上述注入块提供给 agent，agent 可基于这些记忆回答用户关于“上次部署回滚处理方式”的问题，同时需明确区分哪些是历史记录，哪些是模型自身的知识或当前对话内容。
