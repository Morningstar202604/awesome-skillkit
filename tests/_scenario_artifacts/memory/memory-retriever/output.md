### 1. 理解与查询改写

*   **显式意图**：用户想知道一次具体的"部署回滚"操作的处理细节（步骤、原因、结果）。
*   **隐式意图**：
    *   指代消解："上次"指的是最近发生的那一次，需要时近加权。
    *   "那个部署"暗示可能涉及特定的项目或环境（如生产环境、某个微服务），若上文未明确，需扩大检索范围到"部署回滚"这个通用事件。
    *   用户可能想复现该流程，或确认团队是否有标准的回滚 SOP。

**改写后的检索查询（3条）：**
1.  `q1: 部署回滚 处理 步骤` (核心事件)
2.  `q2: 回滚 故障 恢复 记录` (常见关联场景)
3.  `q3: 部署 异常 紧急处理` (兜底召回，防止"回滚"一词未被显式提及但内容相关)

### 2. 检索策略（三路并行）

| 检索路 | 策略细节 | 预期作用 |
| :--- | :--- | :--- |
| **关键词路** | 匹配 "回滚", "部署", "rollback", "发布", "紧急", "SOP"。启用同义词扩展。 | 精确捕获包含这些术语的记忆条目。 |
| **语义路** | 使用 query embedding 检索语义相似的记忆，如"系统出错后如何恢复版本"、"上线失败怎么办"。 | 捕获意图相关但用词不同的记忆（如只记了"生产环境报错恢复"）。 |
| **时近路** | 按 `updated_at` 排序，优先召回最近 3-6 个月内的部署/运维相关记忆。 | 确保命中"上次"这个时间限定，避免检索到半年前的旧流程。 |

### 3. 融合打分与筛选

*   **打分公式**：`score = 0.4×semantic + 0.3×keyword + 0.2×recency + 0.1×confidence`
*   **特殊处理**：
    *   **Disputed 过滤**：如果存在多条关于"回滚处理"的记忆且内容矛盾（如不同人员记录的不同步骤），优先保留 `confidence` 高或 `source` 为官方文档/复盘报告的记忆，并在输出中注明"存在多个版本记录"。
    *   **敏感信息**：若记忆中包含具体的密码、密钥等敏感内容，即使命中也需先进行脱敏或仅注入摘要信息。
*   **相关性下限**：score < 0.3 的条目直接丢弃，不注入。

### 5. 边界情况处置

*   **零召回**：若三路检索均无相关记忆 → 输出"无可信相关记忆"，并建议用户检查是否记忆库中确实未存储此类事件，或指引其创建新的记忆。
*   **低置信度**：若命中的记忆 `confidence < 0.7`（如仅凭用户闲聊提取），必须在注入块旁标注"可能过时，仅供参考"。
*   **预算截断**：若高分记忆总 token 超预算，优先保留"事件详情"（mem_089 类），其次保留"SOP/总结"（mem_102 类），最后保留"通用流程"（mem_055 类）。
