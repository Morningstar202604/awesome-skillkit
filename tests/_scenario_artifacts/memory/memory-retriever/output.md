### 3. 三层记忆检索架构

本系统建议把记忆分成三层，查询在不同层命中不同粒度的信息：

| 层级 | 内容类型 | 与本次查询的关联 | 检索侧重 |
|---|---|---|---|
| **L1 身份/项目层** | 项目名、部署平台、技术栈 | q3 命中 → 决定后续注入的上下文基准 | 关键词为主，语义辅助 |
| **L2 流程/SOP 层** | 部署回滚的标准流程、审批链、工具链 | q1、q2 命中 → 直接回答「怎么处理」 | 语义优先（流程描述长文本）+ 关键词兜底 |
| **L3 事件/痕迹层** | 具体某次回滚的时间、原因、操作人、结果 | q1、q4 命中 → 回答「上次那次」的实例细节 | 时近路强权重 + 关键词 |

**三路并行执行**：
- **关键词路**：BM25 思路，覆盖术语变体（rollback / 回滚 / 撤销 / 回退）。
- **语义路**：向量相似度，捕获「处理方式」「流程」这类抽象匹配。
- **时近路**：按 `updated_at` 降序，重点捞最近 30 天内的 L3 事件条目。

### 4. 融合打分与阈值

采用标准四路加权：

```
score = 0.4×semantic + 0.3×keyword + 0.2×recency + 0.1×confidence
```

- **相关性下限**：score ≥ 0.3，低于则视为「无可信相关记忆」。
- **轮间去重**：若上一轮已注入过相同 mem_id，本轮跳过（身份类核心记忆除外）。
- **主题限额**：同一主题（如「部署平台」）最多取 5 条，防止某主题刷屏。
