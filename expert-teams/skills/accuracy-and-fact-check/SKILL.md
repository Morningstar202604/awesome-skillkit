# 准确性核查与防幻觉（accuracy-and-fact-check）

本 skill 供**全部团队**共用。目标：在交付前对所有关键事实、数字、引用、来源做系统性核查，杜绝幻觉与张冠李戴，让每一个结论性断言都有可追溯的证据支撑。

## 这是什么

一套「断言分级 → 证据定级 → 来源验证 → 反例搜索 → 交叉计算 → 核查报告」的准确性保障规程。核心概念：

**断言三级：**
- **可验证事实**：有客观真伪的陈述（数字、日期、版本、政策条款、引用文献、API 字段）。必须补来源并验证。
- **经验规则**：行业惯例、最佳实践、常见做法（"通常用 X 框架"、"一般阈值设为 Y"）。须标注为经验而非事实，给出来源或说明适用范围。
- **推测建议**：基于推理的判断或建议（"建议采用 A 方案"、"可能导致 B 风险"）。须明确标注为推测，给出推理链条。

**证据强度五级（从高到低）：**
1. 官方文档 / 官方标准 / 一手数据源（官网、GitHub release、国家标准、统计局原始数据）
2. 权威机构 / 学术期刊 / 同行评审论文（DOI 可查）
3. 主流媒体 / 权威技术社区（Reuters、官方博客、Stack Overflow 高赞）
4. 二手转述 / 个人博客 / 聚合站点（须回溯到一级源才采纳）
5. 无来源 / 仅凭记忆（不可作为可验证事实的依据）

## 何时使用

- 任何交付物含**数字**（统计数据、价格、版本号、性能指标、样本量、百分比）。
- 任何交付物含**引用**（文献、政策条款、API 文档、法律条文、标准规范）。
- 任何交付物含**历史事件、时间线、人物、组织**等事实性陈述。
- 团队 lead 做**最终交付汇编前**必须过本 skill（P0 强制）。
- 用户要求"检查一下准确性"、"这个数字准不准"、"有没有幻觉"时。
- 跨团队整合产出，事实来自多个来源需要对齐时。

## 核心步骤

1. **列出全部断言**：通读交付物，把每一个结论性陈述提取为断言清单，标注所在位置（段落/表格/图表）。
2. **给每条断言定级**：按「可验证事实 / 经验规则 / 推测建议」三级分类；可验证事实进一步标注证据强度五级。
3. **可验证断言补来源并验证**：
   - 每条可验证事实必须附来源（URL / DOI / 标准编号 / 版本号 + 抓取时间）。
   - 打开来源原文核对：数字是否一致？引用是否断章取义？版本是否当前有效？URL 是否可访问？
   - 来源强度 ≤4 级时，必须回溯到一级源；无法回溯则降级为 [待核实]。
4. **不可验证项标注**：无法在当前环节验证的断言，标注 `[待核实: 具体验证路径]`，说明需要查什么源、怎么验证，不得脑补来源或假装已验证。
5. **反例搜索**：对每条关键可验证事实，主动搜索至少 **3 条反面证据**（矛盾数据、例外情况、反例场景）。若反例成立，修正断言或标注适用边界；若反例不成立，记录"已排查反例，结论稳健"。
6. **交叉问（换口径算同一数字）**：对关键数字，换一种计算口径或数据源重新核算——例如百分比换绝对数、年化换月度、官方数据换第三方统计——确认数字在不同口径下自洽。
7. **输出核查报告**：包含断言分级表（断言|级别|证据强度|来源|状态）、未核实项清单（含验证路径）、反例排查记录、交叉计算结果。

## 交付前清单

- [ ] 所有可验证事实均已附来源（URL/DOI/版本号+抓取时间），且来源已打开核对。
- [ ] 经验规则与推测建议已明确标注，未与事实混淆。
- [ ] 无来源断言已标注 `[待核实]` 并给出验证路径，未冒充已验证事实。
- [ ] 关键事实已完成 ≥3 条反例搜索，反例排查结果已记录。
- [ ] 关键数字已完成换口径交叉计算，结果自洽或差异已说明。

## 易错点

- **把经验当事实**："大家都用 React"是经验规则不是可验证事实，须标注级别和适用范围，不能写成"React 是唯一选择"。
- **来源张冠李戴**：引用了 A 文章的数据却标注 B 来源，或 URL 指向的页面根本不含该数据。必须打开原文逐字核对。
- **数字改了口径没说**：从"年度增长率"换成"季度环比"却没标注口径变化，导致读者误读。每次换口径必须显式说明。
- **只找支持证据不找反例**：确认偏误——只搜能证明自己对的材料，刻意忽略矛盾数据。反例搜索是强制步骤，不是可选。
- **凭记忆断言**："我记得这个版本是 2.0"——无来源的记忆不可作为可验证事实依据，必须查证或标注 [待核实]。
- **二手源不回溯**：引用了聚合站点的数据却不查原始出处，聚合站可能过时或出错。强度 ≤4 级必须回溯一级源。
