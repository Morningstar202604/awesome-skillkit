# 交付质检门禁（quality-gate-checklist）

本 skill 供**全部团队**共用。目标：在最终交付前，从 7 个维度做系统性质检，确保交付物完整、一致、可追溯、可复现、合规、版权清晰、格式规范。H 级问题不解决不交付。

## 这是什么

一套 7 维交付质检闸门。每个维度有明确的检查项，逐项过单，不合格项按严重度分级：

- **H（High）**：阻断性问题——事实错误、合规红线、版权侵权、核心内容缺失。**H 级不交付**，必须修复或获得用户明确豁免。
- **M（Medium）**：重要问题——一致性偏差、可追溯性缺口、格式不规范。建议修复后交付，若时间紧迫须标注并告知用户。
- **L（Low）**：轻微问题——排版瑕疵、措辞优化、可选增强。可交付后迭代。

**7 维闸门：**

1. **完整性**：交付物是否包含所有承诺的内容？缺什么标什么，不隐藏、不糊弄。
2. **一致性**：术语、口径、风格、编号、配色跨产出是否统一？前后是否矛盾？
3. **可追溯**：每个结论是否有来源？数据/引用/决策是否可回溯到依据？
4. **可复现**：步骤、参数、环境、代码是否可重跑？第三方是否能按文档复现结果？
5. **合规**：是否触碰红线（广告法绝对化用语、敏感词、隐私泄露、伦理问题、违法内容）？
6. **版权**：素材、字体、图片、引用、代码片段是否有授权？是否标注出处？
7. **格式**：是否符合目标平台/场景的规范（尺寸、分辨率、文件格式、字数、排版）？

## 何时使用

- 各团队 **team-lead 最终交付汇编前**（P0 强制）。
- **跨团队整合前**：多个团队产出合并为一个交付包时。
- 用户明确要求"检查一下再交付"、"帮我把把关"、"做个质检"时。
- 交付物涉及对外发布、投稿、上线、印刷等高风险场景时。
- 任何交付物在发送给用户之前的最后一道闸门。

## 核心步骤

1. **逐维过单**：按 7 维顺序，对照下方清单逐项检查交付物。每维给出"通过 / 不通过 / 不适用"判定，不通过项记录具体问题和位置。
2. **不合格项分级**：每个不通过项按 H/M/L 分级，写明问题描述、影响范围、修复建议。
3. **H 级处置**：H 级问题**不交付**。能修复的立即修复，不能修复的必须告知用户并获得明确豁免后才可交付，且须在交付物中标注。
4. **M/L 级处置**：M 级建议修复，时间不允许时标注并告知用户；L 级可交付后迭代，但须记录在案。
5. **输出质检报告**：包含 7 维检查结果汇总表、问题清单（级别|描述|位置|修复建议|状态）、最终门禁结论（通过 / 有条件通过 / 不通过）。

## 7 维质检清单

### ① 完整性
- [ ] 所有承诺的交付物（文档/代码/设计稿/数据/配置）均已包含。
- [ ] 缺失项已明确标注 `[待补: ...]`，未隐藏或假装完成。
- [ ] 各章节/模块/页面无空白占位符（"TODO"、"待补充"未清理）。
- [ ] 交付物覆盖了用户原始需求的全部要点，无遗漏。

### ② 一致性
- [ ] 术语全文统一（同一概念不用多个词，同一词不指多个概念）。
- [ ] 数字/口径/单位前后一致（同一指标不出现两个值）。
- [ ] 风格/语气/排版跨章节统一（标题层级、列表格式、图表样式）。
- [ ] 交叉引用正确（文中提到的图表/章节/编号与实际一致）。

### ③ 可追溯
- [ ] 每个关键结论有来源标注（文献/URL/标准/数据出处）。
- [ ] 关键决策有决策记录（为什么选 A 不选 B，依据是什么）。
- [ ] 数据有出处和采集时间，非凭空生成。
- [ ] 引用格式统一且可定位（DOI/URL 可访问、文献信息完整）。

### ④ 可复现
- [ ] 操作步骤完整可执行（无"略"、"同理"等跳步）。
- [ ] 参数/版本/环境已记录（库版本、操作系统、硬件、随机种子）。
- [ ] 代码/脚本可运行，依赖已声明，输出与文档一致。
- [ ] 第三方按文档可独立复现核心结果。

### ⑤ 合规
- [ ] 无广告法绝对化用语（最/第一/国家级/唯一/顶级，除非有权威认证依据）。
- [ ] 无敏感词/违规内容（政治、色情、暴力、歧视等平台红线）。
- [ ] 无隐私泄露（个人信息、密钥、内部数据未脱敏）。
- [ ] 无伦理问题（涉及人体/动物/未成年人的研究已说明伦理审查）。

### ⑥ 版权
- [ ] 第三方素材（图片/图标/字体/音乐/视频片段）有授权或来自可商用源。
- [ ] 引用内容已标注出处，未超过合理引用范围。
- [ ] 开源代码/库已遵守对应许可证（GPL 传染、MIT 署名等）。
- [ ] 字体已确认授权范围（商用/个人/嵌入），未使用未授权字体。

### ⑦ 格式
- [ ] 文件格式符合目标要求（PDF/PPTX/DOCX/PNG/MP4 等）。
- [ ] 尺寸/分辨率/帧率/码率符合平台规范（如公众号封面 2.35:1、短视频 9:16）。
- [ ] 字数/页数/文件大小在要求范围内。
- [ ] 排版无溢出/错位/乱码，特殊字符（中文/公式/emoji）显示正常。

## 易错点

- **只查格式不查内容**：把质检当成"排版检查"，只看字体对齐不看事实对错。7 维中内容维度（完整性/可追溯/合规）权重更高。
- **自己生成的自己说没问题**：生产者自查有盲区——"我写的当然对"。质检必须以批判性视角逐项过单，必要时派独立角色（如 core-fact-checker）核查。
- **H 级问题带病交付**：发现事实错误或合规红线却因为"快到 deadline 了"先交了再说。H 级必须修复或获得用户豁免，不得默认放行。
- **版权检查走过场**：网上随便找的图就用了，没查授权。商用场景下版权侵权风险极高，必须逐项确认。
- **可复现只写步骤不写参数**："运行脚本即可"但没说 Python 版本、依赖版本、输入数据路径，第三方根本复现不了。
- **一致性只查文字不查数字**：术语统一了但同一个指标在摘要里是 15%、在正文里是 18%，数字矛盾比术语矛盾更严重。
