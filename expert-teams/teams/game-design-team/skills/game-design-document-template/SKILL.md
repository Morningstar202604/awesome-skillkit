# 游戏设计文档模板

本 skill 是各设计角色写 GDD 的结构模板。核心原则：**GDD 写到"照着就能做"——规则无歧义、数值可复算、范围写清楚，不留"到时再定"。** 文档是团队共同基准，模糊会让原型做歪。

## 这是什么

一套游戏设计文档的标准章节结构。规定一份完整 GDD 必须包含哪几块：核心循环、规则、关卡、数值、叙事、经济、美术、UI。各系统设计在自己章节写清楚，接口对齐。

## 何时使用

- gameplay-designer 写核心循环时必加载。
- level/narrative/economy/art 设计师在 GDD 对应章节补充。
- prototype-developer 按 GDD 实现时以本模板章节为索引。
- reviewer 评审设计完整度时对照本模板。

## 核心步骤

1. **核心循环**：一句话写清"开始→行动→反馈→再来一局"，配流程。
2. **规则**：胜利/失败条件、操作方式、基本规则，无歧义。
3. **关卡与难度**：难度曲线、关卡布局、引导（交 level-designer）。
4. **数值**：伤害/成长/掉落公式与表（交 balance-designer，可复算）。
5. **叙事**：世界观、剧情、角色（交 narrative-designer）。
6. **经济**：货币、产出消耗、商店（交 economy-designer）。
7. **美术与 UI**：风格、色彩、视觉规范（交 art-director）。

## 清单

- [ ] 核心循环一句话说清并有流程图。
- [ ] 胜利/失败/操作规则无歧义。
- [ ] 关卡难度曲线写了。
- [ ] 数值公式可复算。
- [ ] 世界观/角色有设定。
- [ ] 货币与产出消耗循环写了。
- [ ] 美术风格与 UI 规范写了。
- [ ] 首版范围明确，标了未实现项。
- [ ] 各系统接口对齐，无矛盾。
- [ ] 没有"到时再定"的黑洞。

## 易错点

- **核心循环说不清**：GDD 写了一堆系统却一句话说不清玩家在干嘛。先写核心循环。
- **规则模糊**："大概""应该"式描述，原型做出来不一致。规则无歧义。
- **数值不可复算**：表格填了数字却没公式，调不动。公式必须可复算。
- **系统互相矛盾**：关卡要求的数值和 balance 给的对不上。接口对齐。
- **范围失控**：GDD 越写越大，首版全做。标首版范围与未实现项。
- **美术喧宾**：美术章节写太细压过玩法。美术服务玩法。
- **留黑洞**：关键处写"待定"。待定项必须标责任人和时间。
