# A/B 实验设计与判定指南

本 skill 是 A/B 实验的工作手册。核心原则：**先定假设和样本量再上线，跑够时间再读数，不看一天就下结论。** 实验的价值在于因果判定，样本量不够、分桶不均，再好看的数字也是噪声。

## 这是什么

一套从实验设计到显著性判定到放量决策的流程。设计阶段定假设、分桶、样本量、护栏；上线后监控 SRM 与样本量；结束后做显著性检验并给能否放量结论。

## 何时使用

- data-experiment-designer 接到"设计 A/B 实验"时必须加载。
- data-statistician 做实验显著性判定时，按本指南选检验方法。
- data-qa-reviewer 复核实验报告时，按本指南检查 SRM/样本量/多重比较。
- data-analysis-team-lead 判断"能不能放量"时使用。

## 核心步骤

1. **定假设**：写出原假设/备择假设，明确核心指标（如转化率从 5% 提到 5.5%）与最小可检测效应 MDE。
2. **算样本量**：给定基线转化率、MDE、显著性水平 α=0.05、功效 1-β=0.8，用样本量公式算每组所需样本量；按日均 UV 折算需要跑几天，通常 ≥7 天覆盖一个完整周。
3. **分桶与随机化**：按用户 ID（非会话）哈希分桶，保证同一用户始终进同组；分流比例常见 50/50 或小流量 10/90 灰度。
4. **设护栏指标**：选定不能变差的护栏（如客诉率、退款率、加载时长），护栏恶化即使核心指标涨也不放量。
5. **跑 SRM 检查**：实际两组样本比是否符合预期分流比，卡方检验 p>0.05 才算分流正常；SRM 异常则实验作废。
6. **显著性判定**：比例用两比例 z 检验，均值用 t 检验；报告 p 值与 95% 置信区间；置信区间跨过 0 则差异不显著。
7. **放量决策**：核心指标显著正向、护栏不恶化、无 SRM 问题 → 放量；否则回滚或迭代。

## 清单

- [ ] 写了原假设/备择假设与核心指标、MDE。
- [ ] 算了每组最小样本量并折算所需天数（≥7 天）。
- [ ] 按用户 ID 哈希分桶，同一用户不跨桶。
- [ ] 设定了护栏指标。
- [ ] 跑了 SRM 检查且 p>0.05。
- [ ] 报告了 p 值与 95% 置信区间。
- [ ] 检查了多重比较（多指标/多分组时做了校正或声明探索性）。
- [ ] 给了明确的放量/回滚结论，不是"好像有提升"。

## 易错点

- **样本量不够就停**：跑了 2 天看到涨就宣布胜利，实际是噪声。必须跑够预估天数。
- **偷看数据反复停**：每天看一次 p 值，显著了就停，会抬高假阳性。要么预设时长，要么做序贯检验校正。
- **SRM 不查**：分流比实际 52/48 但预期 50/50，说明分桶有 bug，结论不可信。先查 SRM。
- **会话级分桶**：同一用户今天 A 组明天 B 组，污染实验。必须用户级哈希。
- **只看核心指标**：转化率涨了但退款率翻倍，这是负优化。护栏指标必须一起看。
- **多重比较不校正**：同时看 10 个指标，总有一个 p<0.05 是运气。声明哪些是探索性的。
